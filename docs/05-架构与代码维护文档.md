## 1. 文档目的与读者

面向全体贡献者：要新增模块、引入依赖、修改跨语言接口前，先读第 2–5 章；要发布版本或处理技术债时，读第 5–7 章；要了解谁对什么负责，读第 10 章治理矩阵。

## 2. 架构守护规则（Architecture Rules）

### 2.1 语言与进程边界

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| AR-1 | Go 与 Rust 之间：消息契约限 Protobuf（控制流）+ Arrow IPC（数据流）；**传输限 IPC 后端（ADR-011）——同机一律 shm（禁 TCP 回环），跨机 gRPC/Flight** | 评审强制；proto 目录 diff 必须架构 owner 评审；CI：代码扫描禁止对 `127.0.0.1/localhost` 建立同机 Go↔Rust 连接（降级链 UDS 除外） |
| AR-2 | 禁止 cgo 调用 Rust，禁止 Rust FFI 调用 Go | CI：Go 构建 `CGO_ENABLED=0`；评审检查 build.rs |
| AR-3 | Rust 代码不得引入集群管理职责（etcd/k8s client 等）；Go 代码不得引入数据处理职责（arrow/parquet 计算依赖） | CI：依赖白名单检查（见 2.4 与 8 章 arch.yml） |
| AR-4 | 共享契约（错误码、指标名、plan 结构）只能定义于 `proto/`，两侧生成，禁止手抄两份 | CI：生成物 diff 校验（make proto-check） |

### 2.2 Rust 侧（engine/）

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| AR-5 | crate 依赖方向单向：`worker/client → plan/exec/shuffle → sql/storage → common`；禁止反向与循环 | CI：cargo-deny 自定义 workspace 依赖图检查 |
| AR-6 | `flux-exec` 不依赖 `flux-sql`（物理层不得反向依赖前端） | 同上 |
| AR-7 | 执行算子禁止在计算线程内做同步 IO/网络调用（一律经异步 IO runtime 或有界 channel 预取） | 评审 + `tokio::task::block_in_place` 禁用 lint |
| AR-8 | 数据面热路径禁止逐行堆分配（Row 编码的 key 路径例外，须注释说明） | 评审（结合 criterion 数据） |
| AR-9 | `unsafe` 仅允许：SIMD intrinsics、Arrow FFI 边界、显式标注的性能关键区；必须 `// SAFETY:` 注释 + 对应测试 | CI：crate 默认 `#![forbid(unsafe_code)]`，白名单 crate 用 cargo-geiger 报告增量 |

### 2.3 Go 侧（control/）

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| AR-10 | 包依赖单向：`cmd → internal/*`；internal 内 `apiserver → jobmanager → scheduler/workermanager → statestore/catalog`，禁止反向 | CI：depguard 规则（golangci-lint） |
| AR-11 | 模块间只依赖消费侧接口（接口定义在使用方包内），禁止跨模块引用具体实现结构体 | 评审 |
| AR-12 | JobManager 状态迁移必须走单一事件循环 goroutine；其他模块不得直接改作业状态 | 评审（状态写路径唯一性） |
| AR-13 | 集群视图（ClusterView）为不可变快照，读侧禁止持锁遍历 | 评审 + `-race` 测试 |

### 2.4 依赖引入策略

**准入原则**：核心链路（sql/plan/exec/shuffle/storage）只引入"标准协议实现"与"无运行时行为侵入"的库；重量级框架一律拒绝。

**Rust 白名单**（版本为初始锁定，升级经 PR 评审）：

| crate | 用途 | 锚定版本策略 |
| --- | --- | --- |
| arrow（含 parquet/flight 子 crate） | 列式类型/IPC/Parquet/Flight | 跟随最新 minor，major 变更需 ADR |
| tonic / prost / prost-types | gRPC 实现 | 跟随稳定版 |
| tokio（含 io-util/sync/fs） | 异步运行时（仅 IO） | 跟随稳定版 |
| object_store | 对象存储统一客户端 | 同上 |
| serde / serde_json | 序列化（配置、manifest） | 同上 |
| thiserror / anyhow（仅工具二进制） | 错误定义 | 同上 |
| tracing / tracing-subscriber | 日志与追踪 | 同上 |
| xxhash-rust | Shuffle 哈希 | 锁定 |
| zstd | 压缩 | 锁定 |
| chrono / time | 时间 | 锁定 |
| uuid / ulid | ID 生成 | 锁定 |
| **nix / rustix** | shm/mmap/eventfd（flux-shmipc 依赖，ADR-011） | 锁定 |
| regex | LIKE/RLIKE（P1） | 锁定 |
| snap | snappy 压缩（Parquet 可选） | 锁定 |
| insta | golden 快照测试（Q2 定案） | 开发依赖 |

**Go 白名单**：

| module | 用途 |
| --- | --- |
| grpc-go / protobuf | RPC |
| log/slog（标准库） | 日志 |
| prometheus/client_golang | 指标 |
| otel（go.opentelemetry.io/...） | 追踪 |
| mattn/go-sqlite3 或 modernc.org/sqlite | StateStore（modernc 优先，纯 Go 免 CGO，与 AR-2 一致） |
| jackc/pgx | Postgres 实现 |
| spf13/cobra（或标准库 flag，M0 定案） | CLI |
| urfave/cli（备选） | CLI 备选 |
| golang.org/x/sys | Windows 命名共享内存/事件适配（shmipc 包，ADR-011） |
| BurntSushi/toml | 配置解析 |

**禁止引入**：DataFusion、Ballista、任何包含执行器/优化器的引擎框架（与 ADR-002 冲突）；JSON 框架类重量依赖（serde_json 之外）；带 cgo 的 crate（与 AR-2 冲突，除非 M2 前评估豁免并记录 ADR）。

**许可证**：仅 Apache-2.0/MIT/BSD/ISC；CI `cargo deny check licenses` + `go-licenses` 守护。新增依赖需在 PR 中按"轻量 ADR"模板说明：动机 / 替代方案 / 许可证 / 维护状态（最近提交、issue 响应）/ 传递依赖数量。

## 3. ADR（架构决策记录）流程

### 3.1 触发条件（满足其一）

1. 引入新依赖或新外部系统；
2. 修改 proto 契约语义（非纯新增字段/方法）；
3. 改变模块职责边界（语言边界、crate 边界、包边界）；
4. 新增顶层目录/交付物（新二进制、新 crate、新服务）；
5. 变更或推翻既有 ADR 决策；
6. 性能预算或兼容策略变更。

### 3.2 流程

提出（issue 模板 `adr:`）→ 起草（模板见 3.3）→ 评审（评审矩阵见 3.4）→ 状态置 Accepted → 实现 PR 引用 ADR 编号 → 反悔时新 ADR 取代（旧文标 Superseded，不删除）。

**存放**：`docs/adr/ADR-0xx-<slug>.md`；编号只增不复用。**现存基线 ADR-001~008 全文见概要设计第 4 章**（迁移到 `docs/adr/` 于 M0 执行）。

### 3.3 模板与示例

```markdown
# ADR-009：流式执行采用微批复用批内核（示例占位，对应概要设计第 13 章预留编号，M5 前评审）

- 状态：Proposed
- 日期：2026-XX-XX
- 决策人：架构 owner、数据面 owner

## 背景
M5 需要流处理能力（FR-S01–S05）。备选：连续流（逐事件）vs 微批（复用批 DAG）。

## 决策
采用微批（间隔可配，默认 500ms）：Source 按批物化 → 复用现有物理计划与算子 →
checkpoint 与 offset 绑定提交。理由：内核复用度（>90% 代码路径）、正确性模型
（批语义已验证）、团队成本。代价：延迟下限受批间隔约束（对目标场景可接受）。

## 备选方案与代价
连续流：延迟最优，但需独立调度/状态模型（估计 3 人月+）且正确性面扩大。

## 影响面
flux-plan（Source/水印算子）、jobmanager（常驻作业类型）、SRS FR-S、详细设计第 X 章。
```

### 3.4 评审矩阵

| 变更类型 | 必需评审人 |
| --- | --- |
| 语言/进程边界、proto 语义 | 架构 owner + 双语言代表各一 |
| 新依赖 | 模块 owner + 架构 owner |
| crate/包内重构 | 模块 owner |
| 文档 | 相关文档 owner |

## 4. 仓库结构与物理布局

```text
flux/
├── CLAUDE.md / README.md / CHANGELOG.md
├── docs/
│   ├── 01-软件需求规格说明书.md … 06-代码规范与开发指南.md
│   ├── adr/                      # ADR-001..00x
│   ├── tech-debt.md              # 技术债登记簿
│   └── sql-compat.md             # SQL 兼容性说明（随版本维护）
├── proto/flux/v1/                 # 唯一契约源（路径与 package flux.v1 对齐；buf 管理）
├── engine/                        # 数据面 · Rust workspace
│   ├── Cargo.toml                 # [workspace.dependencies] 统一版本
│   ├── crates/                    # 目录名 = 包名去 flux- 前缀
│   │   ├── {common,sql,plan,exec,storage,shuffle,shmipc,worker,client}/
│   ├── fuzz/                      # cargo-fuzz 目标
│   └── tests/sqlsem/              # 语义测试用例库（yml）
├── control/                       # 控制面 · Go module
│   ├── cmd/{flux-master,flux}/
│   ├── internal/{apiserver,jobmanager,scheduler,workermanager,shmipc,
│                 catalog,statestore,resultstore,observability,config}/
│   └── migrations/                # StateStore schema 迁移（跟随 statestore）
├── tests/{integration,chaos,soak,compat}/   # 跨组件端到端测试
├── benchmarks/                    # 端到端基准（TPC-H/TPC-DS、BUDGET.md）；criterion 在各 crate benches/
├── deploy/                        # 运维交付物：systemd / docker-compose / Grafana 看板 / 示例配置
├── scripts/                       # 开发辅助（脚手架、codegen、release）
├── ui/                            # Web UI（M3）
└── .github/workflows/{rust,go,proto,arch,bench,release}.yml
```

布局原则：顶层按职责域组织（数据面 / 控制面 / 端到端测试 / 基准 / 运维交付物），语言由目录内工具链文件体现；crate 目录名 = 包名去 `flux-` 前缀（Cargo 包名不变）；`migrations/` 跟随其所属模块（statestore → control/）；端到端测试归 `tests/`，`scripts/` 仅放开发辅助。

物理布局变更必须同步 CLAUDE.md"仓库结构"节（PR 模板检查项）。

## 5. 版本与兼容策略

### 5.1 版本号与节奏

- SemVer：M1–M3 期间 `0.x`（`0.MINOR` 允许破坏性变更，但 CHANGELOG 顶部显式声明）；M3 后进入 `1.0`，此后严格 SemVer。
- 节奏：双周迭代、每月一个发布；发布分支不存在（trunk + tag）。

### 5.2 兼容矩阵（每发布必须复核的表）

| 维度 | 规则 | 验证方式 |
| --- | --- | --- |
| Master ↔ Worker | 同 MINOR 任意混布；跨 MINOR 仅允许"新 Master + 旧 Worker"一个版本窗口（滚动升级）；禁止反向 | `tests/compat/` 组合冒烟 |
| plan_version | 只增；Worker 拒绝高于自身的计划版本（4008） | proto fuzz + 单测 |
| 落盘格式 | Parquet/Arrow 由标准保证；`_commit/manifest` schema 变更需向后兼容读取（新增字段可选） | 迁移测试 |
| StateStore schema | `control/migrations/` 带版本号脚本，升级自动执行、降级不支持 | 迁移测试 |
| gRPC API | 方法只增不改；字段只增（reserved 兜底） | buf breaking |
| REST（P1） | 路由变更视为破坏性 | 契约测试 |
| CLI | 命令/参数废弃走"标记弃用 → 2 个版本 → 移除" | 帮助快照 |

### 5.3 分支与发布流程

- **Trunk-based**：`main` 唯一长期分支；特性短分支（≤ 3 天）+ PR 评审合入；禁止直 push `main`（CI 强制）。
- 发布 runbook（发布负责人按序执行，缺一不可）：

```text
1. 确认 main 全绿（CI + 夜间基准 + soak 最近一次通过）
2. 核对第 5.2 节兼容矩阵，结论写入 CHANGELOG 兼容性小节
3. 核对性能预算表（benchmarks/BUDGET.md）：无超预算项，或有已批准的例外说明
4. cargo audit / govulncheck：高危 = 0
5. CHANGELOG 更新（Keep a Changelog 格式，含破坏性变更/已知问题/兼容结论）
6. 打 tag vX.Y.Z → release.yml 自动构建多平台二进制 + 校验和
7. 产物冒烟：docker/裸机各拉起一次 dev-cluster + TPC-H 1 条查询
8. 公告（如为公开版本）：release notes + 社区渠道
```

## 6. 性能预算与回归守护

**预算表**（`benchmarks/BUDGET.md`，每项含预算值/最近值/趋势）：

| 层级 | 指标 | 预算（示例，M2 校准后锁定） |
| --- | --- | --- |
| 算子 | Parquet 扫描吞吐（单核） | ≥ 150MB/s |
| 算子 | HashAgg 吞吐（group 基数 1e6） | ≥ 10M rows/s |
| 算子 | HashJoin 探测吞吐 | ≥ 20M rows/s |
| 算子 | Shuffle 编解码开销 | < 纯拷贝 × 1.3 |
| 端到端 | TPC-H 10GB 总时（单机 8C） | 预算随基线锁定 |
| 资源 | Worker 空载 RSS | ≤ 200MB |

**CI 分级**：

| 级别 | 触发 | 内容 | 门槛 |
| --- | --- | --- | --- |
| 每 PR | 受影响 crate | criterion 微基准对比 | 回归 > 5% 须说明或修复 |
| 每夜 | main | TPC-H 10GB 单机全量 + 语义集 + chaos 冒烟 | > 3% 报警（issue 自动建） |

## 7. 技术债管理

**登记簿**：`docs/tech-debt.md`，条目字段：编号 / 描述 / 影响模块 / 利息（不还的代价，分 正确性·性能·可测性·交付速度 四类并评级）/ 偿还窗口 / owner / 状态。

**规则**：

1. 允许为赶里程碑借债，但 PR 必须 `tech-debt:` 前缀登记（禁止隐性负债）；
2. 每月迭代预留 20% 容量偿还高利息债务；
3. 正确性/性能类 P0 债务不得跨 MINOR 版本累积超过 2 条。

**初始登记（v0.2，随文档定稿）**：

| 编号 | 描述 | 利息 | 窗口 | 状态 |
| --- | --- | --- | --- | --- |
| TD-001 | 流式章节（FR-S）设计仅有概要规格 | 交付速度（M5 风险） | M4 前补 ADR-011 与详细设计 | Open |
| TD-002 | 调度器公平份额仅设计未实现（FR-CL03 P2） | 交付速度 | M4 | Open |
| TD-003 | 单机与集群的计划序列化路径未完全合一（单机可绕过 proto） | 可测性 | M2 末 | Open |
| TD-004 | CLI 框架选型未定（cobra vs 标准库） | 交付速度 | M0 | Open |
| TD-005 | `insta` golden 工具引入未定案（规范 Q2） | 可测性 | M1 前 | Open |
| TD-006 | CSV/JSON 写路径未设计（读优先） | 功能完整性 | P2 | Open |

## 8. CI/CD 总览

| 工作流 | 触发 | 内容 |
| --- | --- | --- |
| `rust.yml` | PR | fmt + clippy（-D warnings）+ cargo test + coverage + cargo-deny（licenses/advisories）+ fuzz smoke |
| `go.yml` | PR | gofmt + golangci-lint + go test（-race）+ `CGO_ENABLED=0` 构建校验 |
| `proto.yml` | proto/** | buf lint + breaking + 双侧生成一致性 |
| `arch.yml` | PR | AR-3/5/6/10 依赖方向自动检查 |
| `bench.yml` | 每夜/每版本 | 第 6 章性能守护 |
| `release.yml` | tag | 多平台产物 + 校验和 + CHANGELOG 发布 |

`rust.yml` 核心（草图）：

```yaml
name: rust
on: { pull_request: { paths: ["engine/**"] } }
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with: { components: "rustfmt, clippy" }
      - run: cargo fmt --all -- --check
      - run: cargo clippy --workspace --all-targets -- -D warnings
      - run: cargo test --workspace
      - run: cargo install cargo-deny && cargo deny check licenses advisories
  arch:
    steps:
      - run: cargo deny check bans --config deny-ar-rules.toml   # AR-5/6 依赖图
```

`arch.yml` Go 侧（depguard 草图）：

```yaml
linters-settings:
  depguard:
    rules:
      data-plane-forbidden:
        files: ["**/control/**"]
        deny:
          - { pkg: "github.com/apache/arrow/go", desc: "AR-3: Go 不做数据处理" }
          - { pkg: "github.com/parquet-go/parquet-go", desc: "AR-3" }
      reverse-deps:
        files: ["**/internal/statestore/**", "**/internal/catalog/**"]
        deny:
          - { pkg: "**/internal/jobmanager", desc: "AR-10: 禁止反向依赖" }
          - { pkg: "**/internal/apiserver", desc: "AR-10" }
```

## 10. 治理矩阵（RACI）

| 事项 | 负责(R) | 批准(A) | 咨询(C) | 知会(I) |
